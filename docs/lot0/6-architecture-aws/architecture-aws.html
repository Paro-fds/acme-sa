Architecture AWS : schéma, coûts, VPN et base de données

Comment le portail sera hébergé sur le compte AWS d'ACME SA, combien cela coûte chaque mois, comment l'espace RH est réservé au réseau de l'institution, et pourquoi PostgreSQL.

Version 0.1 du 7 octobre 2026, proposition à discuter avec la DIT. Ce qui vient du registre cite sa source (Q8). Les éléments marqués [à confirmer] attendent la DIT. Les coûts sont des estimations : prix publics à la demande d'AWS, en dollars américains, hors taxes, à vérifier dans le calculateur officiel d'AWS (AWS Pricing Calculator) avant de les présenter.

Ce que le registre fixe déjà (Q8)

  • Hébergement sur le compte AWS d'ACME SA compte existant, géré par la DIT (précisé le 07/10/2026), à l'adresse carriere.acmehaiti.com ; région [us-east-2, à confirmer par la DIT], celle de Cognito.
  • HTTPS uniquement, certificat ACM, CloudFront en frontal.
  • Deux environnements : production, et recette sur recette-carriere.acmehaiti.com, protégée par mot de passe, données fictives seulement.
  • Documents dans un S3 privé, chiffré, versionné ; liens temporaires ; analyse antivirus au dépôt.
  • Base PostgreSQL gérée (RDS) recommandée, sauvegardée chaque jour, conservée 30 jours.
  • Comptes RH : double authentification (Cognito, SES) ; espace d'administration réservé au réseau de l'institution ou au VPN institutionnel. Secrets dans AWS Secrets Manager.

4. Réserver l'espace RH au réseau de l'institution

Le registre demande que l'administration soit « réservée au réseau de l'institution ou accessible via VPN institutionnel » (Q8 §4). Trois façons de le faire :

OptionCommentCoûtPourContre
A. Liste d'IP au pare-feu (recommandée)Le WAF n'accepte /admin et /api/admin que depuis les adresses IP publiques de l'institution. Les RH et les administrateurs travaillent depuis les bureaux (précisé le 07/10/2026) : aucun VPN n'est nécessaireCompris dans le WAF (~10 $)Simple ; aucun équipement ; s'ajoute à la double authentificationIl faut des IP publiques fixes pour chaque bureau [à confirmer par la DIT]
B. VPN site à siteUn tunnel chiffré entre le pare-feu de l'institution et le VPC ; l'espace RH n'a plus d'adresse publique~ 37 $ par moisL'espace RH devient invisible depuis InternetIl faut un pare-feu compatible IPsec côté institution, et le configurer ; plus complexe
C. AWS Client VPNChaque RH installe un logiciel VPN sur son poste~ 75 $ par mois et plusFonctionne de partoutLe plus cher ; un logiciel à gérer sur chaque poste ; fait doublon avec le VPN institutionnel

Dans les trois cas, les comptes RH gardent la double authentification Cognito : le réseau ne remplace pas le mot de passe et le code.

5. La base de données

  • PostgreSQL sur RDS : c'est ce que recommande le registre (Q8 §3), et le choix SQL que justifie le modèle de données (§13 : données très liées, opérations qui doivent réussir ensemble, schéma stable, petit volume).
  • Taille : une petite instance suffit pour ~500 employés et quelques milliers de certificats. On peut l'agrandir en quelques minutes si besoin.
  • Sauvegardes : automatiques chaque jour, conservées 30 jours (Q8 §3), avec restauration à n'importe quelle minute de ces 30 jours. Les documents S3 sont versionnés : un fichier écrasé ou supprimé se récupère.
  • Sécurité : chiffrée, dans un sous-réseau privé ; seule l'application peut s'y connecter ; mot de passe dans Secrets Manager.
  • Une seule zone ou deux (Multi-AZ) ? Une seule. Un arrêt de quelques heures est acceptable (précisé le 07/10/2026) : la base sur deux zones (+25 $ par mois) n'est pas nécessaire au lancement. À confirmer par le directeur (ENF-23). En cas de panne d'une zone, la base serait restaurée en moins d'une heure, mais le portail serait arrêté pendant ce temps.
  • Tests de restauration : à faire régulièrement, fréquence [à fixer avec la DIT] (ENF-22).
  • Le passage de la base actuelle du MVP (SQLite) à PostgreSQL se fait sans perte de données (conception technique, B-18).
